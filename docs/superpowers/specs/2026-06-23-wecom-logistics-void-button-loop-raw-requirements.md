## 初步验收断言

- [ ] 使用问题“九机物流单详情，什么情况下显示作废按钮”时，不应无限工具调用或长时间只有心跳。
- [ ] Agent 命中候选文件后应收敛到证据读取、阶段性总结或 Human Loop，不应继续跨仓库宽泛搜索。
- [ ] 工具调用达到上限或重复时，应进入已有恢复总结链路，而不是等待 LangGraph 递归上限。
- [ ] 工具调用过程说明不应作为普通最终正文累积。
- [ ] 恢复总结路径不能因为无法调用 `runtime_todolist_update` 而再次触发运行时审核失败；非 SQL 审核项应由程序化证据补齐。
- [ ] 恢复总结路径不得覆盖 SQL 正确性审核的 blocked 状态。
- [ ] 默认工具调用上限不能过低；跨仓库代码定位应有足够空间读取候选页面/API/服务代码，不能在 8 个证据工具结果附近提前恢复总结。

## 不适用或暂缓项

- 不涉及数据库结构变更。
- 不涉及 HTTP API 契约变更。
- 本地 Docker 无 `wecom-agent` 容器，远端运行日志无法直接读取；通过本地真实 Agent 探针复现。
