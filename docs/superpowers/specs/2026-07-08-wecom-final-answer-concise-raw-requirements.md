## 初步理解

- 当前项目已有过程/结论分离、企业微信排版、最终回复闸门和业务节点审核规则，但最终回答的“短答案优先、按需展开、少标题、少候选”的门槛不够明确。
- 本次优化目标是让企业微信最终回复默认更短、更直接：先结论，保留最小证据和最小下一步，避免把检索过程、候选路径、审核项、TodoList 或多轮状态揉进最终正文。
- 不改变 Agent 主链路，优先通过业务提示词、路由基础提示词、审核提示词和最终回复闸门共同约束输出质量。

## 验收断言

- [x] 最终回答默认采用“结论 + 依据 + 建议/下一步”的短结构；简单事实类问题允许只输出 1~3 行。
- [x] 复杂问题只在用户明确要求流程、方案、SQL、对比或详细排查时展开。
- [x] 最终回答不得输出内部审核项、TodoList、自检清单、工具过程、重复候选路径或连续阶段性状态。
- [x] 最终回复闸门能识别结构杂乱、过程过多、标题过多、与问题不相关内容过多的候选回答，并要求继续压缩或修正。
- [x] 测试覆盖业务提示词、审核提示词和最终回复闸门提示词中的简洁输出约束。
