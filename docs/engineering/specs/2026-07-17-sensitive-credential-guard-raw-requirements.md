# 敏感凭据提问前置拦截原始需求

Last Updated: 2026-07-17

## 用户原始需求

> /dev-spec-gen 优化 wecom 项目，针对询问内部账号密码等安全敏感信息的问题，直接在前置入口拦截，不允许进入 Agent 查询和回答流程。

## 需求解释

- 目标场景：用户直接索要、查询、读取、导出或要求展示账号密码、登录凭据、Token、API Key、Secret、Cookie、Session、私钥等认证秘密。
- 典型命中：仅给出某系统或某账号名称并询问其“账号密码”，即使没有“查询/告诉我”等动词也应拦截。
- 拦截位置：企业微信消息进入图片分析、会话历史写入、Planner、LLM、MCP 工具和 Agent 流程之前，使用本地确定性规则判断。
- 拦截回复：只说明触发敏感凭据安全策略和本轮未调用查询工具；不回显用户原问题，不记录或展示秘密值。
- 审计日志：只记录消息 ID、机器人、会话标识、命中分类和凭据类型，不记录完整提问或命中原文。
- 安全技术讨论、密码重置、Token 轮换、登录失败排查、鉴权逻辑、脱敏存储和前置拦截实现等问题允许继续处理。
- 已包含敏感参数的业务排障文本不会仅因出现 `pwd=`、`token=` 等字段就自动拦截；只处理“索要或提取凭据”的意图，避免破坏现有接口排障能力。
- 主消息与引用消息中的文本、语音识别结果、图文混排文本均参与前置判断；纯图片内容本轮不做 OCR 级安全识别。

## 验收标准

- [x] 直接询问某账号或系统的账号密码时立即返回安全拦截提示。
- [x] 询问密码具体值、Token、API Key、Secret、Cookie、Session 或私钥时立即拦截。
- [x] 要求从配置文件、环境变量、数据库、代码或日志中读取、导出凭据时立即拦截。
- [x] 被拦截请求不进入图片分析、Planner、LLM、MCP、Agent 和会话历史写入流程。
- [x] 拦截日志不包含用户原始问题、命中原文和任何秘密值。
- [x] 密码重置、凭据轮换、登录失败、Token 过期、敏感信息脱敏、鉴权代码或拦截实现等安全治理问题不误拦截。
- [x] 现有带 `pwd=` 参数的接口排障用例不回归。
- [x] 引用敏感问题进行安全规则讨论时不误拦截。
- [x] TypeScript 编译、目标自动化测试和交互控制回归通过。

## 测试 seam

- 核心规则：`src/tests/test-sensitive-request-guard.ts` 验证阻断、放行、主消息/引用消息文本提取、审计脱敏和企微入口顺序。
- 兼容入口：`src/tests/test-sensitive-credential-guard.ts` 验证兼容模块复用统一守卫，不维护第二套规则。
- 适配层静态验证：前置守卫调用位于 `parseWeComMessage` 和 MCP 工具加载之前。
- 回归样本：密码重置、Token 过期、鉴权逻辑、带敏感参数的 curl 排障和引用内容安全讨论。

## 非目标

- 不实现完整 DLP、PII 或机器学习分类器。
- 不扫描纯图片中的凭据内容。
- 不自动重置密码、读取密钥或执行权限申请。
- 不修改企业微信 SDK、MCP 服务端或依赖模型提示词作为主要拦截手段。
- 不提交或推送 Git 变更。

## 实现与验证证据

- 企业微信前置接入：`src/wecom-adapter.ts`。
- 自动化测试：`src/tests/test-sensitive-request-guard.ts`、`src/tests/test-sensitive-credential-guard.ts`。
