# 敏感凭据请求前置拦截原始需求

Last Updated: 2026-07-17

## 用户原始需求

> 使用技能/dev-spec-gen 优化wecom项目，ch999oanew的账号密码, 问这种安全性问题的, 直接前置拦截, 提问敏感信息直接拦截不查工具, 并提示用户后台已记录该行为

## 需求解释

- 作用范围：企业微信机器人收到的当前用户消息。
- 核心场景：用户直接或变相索取账号、密码、Token、Secret、API Key、Cookie、私钥等认证凭据的真实值，例如“ch999oanew 的账号密码是什么”。
- 拦截位置：必须早于图片识别、模型调用、MCP 工具加载、工具路由和任何证据查询。
- 判定方式：使用本地确定性规则检查原始文本、语音识别文本、图文混排中的文本以及引用消息文本，不依赖模型判断。
- 用户反馈：明确说明该请求涉及敏感凭据、已被系统拦截、本轮未调用查询工具，并提示该行为已被后台安全审计记录。
- 审计记录：后台输出结构化安全日志，记录事件类型、时间、机器人、消息、会话、用户、聊天类型和命中类别；不记录用户原始问题和任何凭据值。
- 误拦截控制：密码修改、重置、过期处理、规则咨询、安全配置等不索取真实凭据值的问题允许继续处理。

## 验收标准

- [x] “ch999oanew 的账号密码是什么”在进入消息解析和工具加载前被拦截。
- [x] 索取密码、Token、Secret、API Key、Cookie、私钥等真实值的常见表达被拦截。
- [x] “如何修改密码”“密码过期怎么办”“密码规则是什么”等安全操作咨询不被拦截。
- [x] 命中后不调用图片识别、基础模型、MCP 工具或 Agent 图。
- [x] 命中后向用户返回固定安全提示，并明确“后台已记录该行为”。
- [x] 后台生成结构化审计日志，且日志不包含原始问题、密码、Token、Cookie 或 Secret 值。
- [x] 现有帮助指令、环境切换、会话清理和正常问答行为不回归。

## 测试 seam

- 单元测试：新增 `src/tests/test-sensitive-request-guard.ts`，覆盖命中、放行、审计脱敏和原始消息文本提取。
- 适配层静态验证：确认安全预检调用位置早于 `parseWeComMessage` 和 `getAllMcpTools`。
- 类型验证：`npx tsc --noEmit --pretty false`。
- 回归验证：执行与企微适配、配置、MCP 工具缓存相关的现有测试。

## 非目标

- 不实现账号密码重置或凭据申请流程。
- 不查询、读取、缓存或返回任何真实凭据。
- 不把安全规则交给大模型自由判断。
- 不提交或推送 Git 变更。

## 代码发现记录

- 当前环境未提供 GitNexus MCP 调用能力，已记录为工具受限。
- 使用本地 `rg` 兜底定位：消息入口位于 `src/wecom-adapter.ts` 的 `bot.on("message")`；MCP 加载位于同文件 `getAllMcpTools` 调用；现有敏感参数过滤位于 `src/interaction-control.ts`，用途仅为会话锚点过滤，不能承接本需求。
