# 企业微信会话过期时间调整原始需求

Last Updated: 2026-07-19

## 用户原始需求

> 使用技能/dev-gen-spec 优化wecom 项目，1. 会话时长改为1小时

## 需求解释

- 作用范围：`wecom-agent` 内存会话管理器 `SessionManager`。
- 当前行为：会话在连续 30 分钟无活动后，于下一次带过期检查的访问中清空会话历史及关联状态。
- 目标行为：保持现有“按最后活动时间计算”的语义，将无活动过期时间调整为 1 小时。
- 活动续期：每次获取会话、追加消息或更新会话状态后，继续刷新 `lastActivity`；活跃会话不按创建时间强制结束。
- 过期清理范围保持不变：消息历史、当前项目提示、MCP Header 覆盖、当前环境切换命令、待处理人工确认、压缩标记和会话记忆图。
- 边界：本需求不修改企业微信流式回复 TTL、MCP 工具缓存 TTL、人工确认请求 TTL。

## 验收标准

- [x] 会话连续无活动不足 1 小时时，历史消息和关联会话状态继续保留。
- [x] 会话连续无活动超过 1 小时时，下一次过期检查会清空历史消息和现有关联会话状态。
- [x] 过期后返回的仍是同一个可继续使用的会话对象，并将 `lastActivity` 更新为当前时间。
- [x] 新会话创建、主动清理、历史压缩和项目/环境切换行为不受影响。
- [x] TypeScript 编译及目标会话过期测试通过。

## 测试 seam

- 新增 `src/tests/test-session-expiration.ts`，通过替换 `Date.now` 构造确定性时间边界。
- 正向用例：创建会话并写入消息、项目提示和 MCP 环境状态，经过 59 分 59 秒后仍保留。
- 过期用例：继续推进到超过 60 分钟后触发过期检查，验证消息与关联状态均被清空。
- 回归验证：执行 `npx tsc --noEmit --pretty false`，并运行现有会话/项目切换相关测试。

## 非目标

- 不新增环境变量或配置项。
- 不修改 `HUMAN_LOOP_TTL_MS`、`STREAM_SAFE_TTL_MS` 或 MCP 工具缓存配置。
- 不重构会话存储结构，不引入 Redis 或持久化数据库。
- 不执行 Git 暂存、提交、推送或部署。

## 代码发现记录

- 当前环境未提供 GitNexus MCP 调用能力，使用本地仓库检索进行兜底核对。
- 会话过期实现位于 `src/session-manager.ts`：`SESSION_EXPIRATION_MS = 30 * 60 * 1000`，并由 `getOrCreateSession(sessionKey, true)` 触发过期判断。
- 主要调用方位于 `src/wecom-adapter.ts` 和 `src/mcp-client.ts`；已有项目切换回归测试使用独立 `SessionManager` 实例。
- 工作区存在多项用户未提交修改，本次只触碰会话过期需求对应文件和新增文档/测试，不覆盖其他改动。

## 当前决策

- “会话时长 1 小时”解释为“连续无活动 1 小时后过期”，沿用当前滑动续期机制。
- 维持当前严格大于阈值才过期的判断，即恰好 60 分钟时仍未触发，超过 60 分钟后触发。
- 当前 frontier：先增加失败测试，再最小修改过期常量，最后执行编译与相关回归。
- Blocking edges：无。
