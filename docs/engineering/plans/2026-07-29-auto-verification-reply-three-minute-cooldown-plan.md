# 自动核实最短持续时间与兜底退出实施计划

Last Updated: 2026-07-29

**Goal:** 从每次用户提问进入处理时启动固定 3 分钟窗口；窗口内判定证据不足时继续调用工具且不刷新起点，窗口外再次证据不足时发送兜底，同时以提问处理开始后的 8 分钟作为硬上限。

**Raw Requirements:** `docs/engineering/specs/2026-07-29-auto-verification-reply-three-minute-cooldown-raw-requirements.md`

**Tech Stack:** TypeScript 6、Node.js ESM、企业微信流式回复、内存会话状态、脚本式 TypeScript 测试。

## 当前已确认设计

- 隔离维度：`sessionKey`。
- 私聊键：`single:{fromUser}`。
- 群聊键：`group:{chatId}:{fromUser}`。
- 自动核实固定窗口：180,000 毫秒。
- 窗口起点：本次用户提问进入 Agent 处理时已有的 `streamStartedAt`。
- 固定窗口内的 `unresolved + continue` 结果触发新一轮工具核实，不刷新窗口起点。
- 从用户提问时间起严格超过阈值后，再次出现 `unresolved + continue` 时触发兜底退出。
- 任务硬上限：从同一用户提问时间计算 8 分钟；达到上限时兜底退出。
- 已通过评审的最终结论可随时立即发送。
- 3 分钟规则只处理 `unresolved + continue`；Human Loop、真实模型错误、工具错误上限和流式过期立即沿现有路径退出。
- 每轮续查至少获得一个新的证据工具结果；TodoList 更新和完全相同的“工具名 + 参数”不计入。
- 无新证据时携带剩余缺口和已调用参数纠偏一次；仍无进展时立即返回明确的工具无进展原因，不进入证据不足兜底。
- 保留现有全局重复调用上限；重复调用可以执行但不计入新证据，仅有重复调用的轮次进入无进展纠偏。

## 代码落点候选

- `src/wecom-adapter.ts`：把 Agent 执行、最终评审和续查组织为有界循环，复用任务开始时间与流式心跳。
- `src/runtime-todolist.ts`：保持最终评审结果语义稳定；如需独立纯函数，仅承载续查/退出判定。
- `src/tests/test-final-reply-delivery.ts`：保留兜底文案、真实错误、Human Loop 和正常结论回归。
- 建议新增自动续查策略测试，使用可注入时间覆盖 3 分钟边界和安全退出。

## 设计约束

- 自动续查只能由真实的 `unresolved + continue` 结果触发。
- 每轮续查必须保持当前 `activeTask`，并持续维护企业微信流式心跳。
- 不允许用全局计时影响其他用户或群聊。
- 已通过评审的正常最终结论不等待 3 分钟。
- 真实模型错误、工具保护上限和流式过期必须保留可控退出路径。
- 自动续查要继承已有工具证据并抑制相同范围的无效重复调用。
- 时间来源需要具备确定性测试 seam。
- 保留工作区已有暂存和未跟踪文件，不执行无关格式化或重构。
