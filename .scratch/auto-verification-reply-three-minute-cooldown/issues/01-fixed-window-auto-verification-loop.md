# 01 — 固定三分钟窗口的自动续查闭环

**What to build:** 当最终评审在用户提问后的三分钟保护窗口内认为证据不足且要求继续时，Agent 保持当前任务并真正开始下一轮工具核实；严格超过三分钟后，只在下一次同类证据不足判定时发送现有兜底回复。有效结论可随时立即发送，整项任务达到八分钟时有界退出。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 每次用户提问进入处理时只记录一次任务开始时间，续查轮次不刷新该时间。
- [ ] 经过时间小于或等于 180,000 毫秒时，`unresolved + continue` 不发送最终兜底并实际调用下一轮 Agent 工具执行。
- [ ] 确定性测试覆盖 179,999、180,000 和 180,001 毫秒，证明只有严格超过三分钟后的下一次证据不足判定才兜底退出。
- [ ] 任意时刻评审通过后立即发送正常结论，不等待三分钟。
- [ ] 经过时间达到 480,000 毫秒时停止查询并发送一次现有兜底回复。
- [ ] 使用可注入时间、假 Agent 轮次和假最终评审器的编排测试，不依赖真实企业微信、WebSocket、模型或 MCP。
- [ ] 现有证据不足兜底文案保持不变。
