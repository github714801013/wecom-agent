# 自动核实最短持续时间与兜底退出原始需求

Last Updated: 2026-07-29

## 用户原始需求

> /dev-spec-gen 使用这个技能优化 com-agent 项目，触发这个回复：“已自动继续核实，但本轮仍未获得足够完整的直接证据。”前后需要相差 3 分钟，避免一直触发这个回复。
>
> 规则澄清：Agent 继续调用工具查，直到超过 3 分钟；超过 3 分钟后再次触发证据不足判定，才停止查询。

## 术语

- **证据不足判定**：最终回复评审返回 `ready=false`、`action=continue`、`source=unresolved` 的结果。
- **自动续查**：证据不足判定发生且尚未满足退出条件时，保持当前任务活跃，携带已有问题、候选回答和工具证据再次进入 Agent 工具调用循环。
- **兜底退出**：持续核实时间超过 3 分钟后，再次发生证据不足判定时，停止自动续查并由 `buildBlockedFinalReply` 生成有界兜底回复。
- **会话键（sessionKey）**：私聊使用 `single:{fromUser}`；群聊使用 `group:{chatId}:{fromUser}`。

## 已确认需求

- 自动核实固定窗口为 3 分钟，即 180,000 毫秒。
- 3 分钟从本次用户提问进入 Agent 处理时开始计算，不按 session 创建时间计算。
- 证据不足判定发生在提问后的 3 分钟内时，不发送兜底回复，Agent 继续调用工具核实。
- 续查期间再次发生证据不足判定时，不刷新 3 分钟计时起点。
- 从用户提问时间起严格超过 3 分钟后，再次判定证据不足时，Agent 停止查询并发送兜底回复。
- 任务总时长设为 8 分钟硬上限，同样从本次用户提问进入 Agent 处理时开始计算；达到上限时停止查询并发送兜底回复，为 9 分钟流式安全 TTL 预留 1 分钟。
- 3 分钟自动续查只适用于 `source=unresolved` 且 `action=continue`。
- 每轮自动续查必须获得至少一个新的证据工具结果；`runtime_todolist_update` 和完全相同的“工具名 + 参数”不计入新证据。
- 续查轮次未获得新证据时，携带剩余证据缺口和已调用工具参数强制纠偏重试一次。
- 纠偏后仍无新证据时，立即按工具无进展退出，明确返回无法产生新的有效工具查询；不等待 3 分钟，也不转换为证据不足兜底。
- 保留现有全局重复工具调用上限；重复调用可以执行，但不计入新证据。仅包含重复调用的轮次按无新证据规则处理。
- 正常最终结论一旦通过评审，可以结束自动续查并立即发送。
- `action=human_loop`、`source=error`、工具错误上限和流式过期沿现有路径立即结束，不等待 3 分钟，也不转换为证据不足兜底。
- 隔离范围按 `sessionKey`；私聊中不同用户互不影响，群聊中不同群或不同发送者互不影响。

## 代码事实

- 固定回复位于 `src/wecom-adapter.ts` 的 `buildBlockedFinalReply`。
- 当前每个用户任务只启动一次 `agent.stream` 工具循环，循环结束后调用一次 `resolveFinalReplyWithModel`。
- `resolveFinalReplyWithModel` 返回 `source=unresolved`、`action=continue` 后，当前代码不会重新进入 Agent 工具循环，而是由 `resolveFinalReplyDelivery` 直接构造兜底回复。
- 当前代码在每次用户消息进入处理时记录 `streamStartedAt = Date.now()`；该时间可同时作为固定 3 分钟窗口和 8 分钟任务硬上限的起点，无需写入 session 或在续查时刷新。
- `agent.stream` 的工具调用受 `recursionLimit` 和单轮工具结果保护上限约束，自动续查仍需保留这些安全退出。
- `safeReplyStream(content, true)` 用于结束当前企业微信流式回复；续查期间应保持 `activeTask` 和流式心跳有效。
- `SessionManager` 已按 `sessionKey` 保存内存会话状态，连续无活动 1 小时后清理。
- 现有时间相关测试通常通过可注入的 `now` 或替换 `Date.now` 构造确定性边界。

## 待确认规则

- 无。

## 初步验收方向

- [ ] 用户提问进入处理后的 3 分钟内判定证据不足时，不发送兜底并进入下一轮工具核实。
- [ ] 每轮续查继承当前问题和已有证据，并至少获得一个新的证据工具结果；TodoList 更新和完全相同的工具调用不满足该条件。
- [ ] 首次无新证据时使用剩余缺口和已调用参数纠偏一次；第二次仍无新证据时立即返回明确的工具无进展原因。
- [ ] 保留全局重复调用上限；重复调用可以执行但不计入新证据，重复调用轮次不能绕过无进展保护。
- [ ] 3 分钟窗口内后续判定证据不足时继续续查，且不刷新用户提问时间起点。
- [ ] 从用户提问时间起严格超过 3 分钟后再次判定证据不足时，停止续查并发送一次兜底回复。
- [ ] 任务总时长达到 8 分钟时强制停止续查并发送兜底回复。
- [ ] 任何时刻形成通过评审的最终结论时立即发送，无需等待满 3 分钟。
- [ ] 正常结论、Human Loop、真实模型错误、工具错误上限和流式过期立即退出，且不会被转换为证据不足兜底。
- [ ] 不同 `sessionKey` 的任务和计时互不影响。
- [ ] 自动续查期间企业微信流式心跳持续，最终退出时流式卡片正确结束。
- [ ] 使用确定性时间测试覆盖保护期内、临界点、保护期外及安全上限。

## 非目标

- 不改变最终回复评审模型的证据判断规则。
- 不修改固定兜底回复的文案。
- 不调整企业微信流式回复 TTL、Human Loop TTL 或会话过期时长。
- 不引入与本需求无关的重构。
- 不执行 Git 暂存、提交、推送或部署。
