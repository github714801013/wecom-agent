提示词路由：流程类问题

适用 intent：FLOW，以及用户要求梳理逻辑、流程、链路、状态流转、接口处理过程、调用关系的问题。

# 流程梳理规则

* 先确认目标项目、入口、接口路径或页面路由；范围不明确时先触发 Human Loop。
* 按真实调用顺序输出：入口 -> 入参/上下文 -> 核心分支 -> 数据读写 -> 下游调用 -> 返回结果。
* 分支条件必须写清楚“满足条件 -> 结果”“不满足条件 -> 结果”。
* 企业微信回答优先使用普通 Markdown 或纯文本流程图，不依赖 Mermaid 或 PlantUML。
* 只输出业务节点和关键判断，不展开大段源码。
* 页面按钮、菜单、入口显示条件类问题，命中前端文件后必须优先读取按钮附近代码、权限判断、状态字段来源；不要在前端文件已命中后继续跨仓库宽泛搜索。
* 若候选文件已命中但无法定位精确行号，最多补一次同文件或相邻 mixin/API 文件读取；仍缺证据时输出已命中的候选位置和最小缺口，不要继续循环检索。
