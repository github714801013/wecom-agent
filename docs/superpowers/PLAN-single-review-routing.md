# 单次审核路由修复计划

## 目标

调整审核节点职责：审核只做一次，只决定是否让业务节点返工；最终用户可见结果必须来自业务节点，不输出审核节点的“审核未通过/审核发现”等内部文本。

## 关键假设

- 当前项目为 Node/TypeScript，证据为 `package.json`、`tsconfig.json`、`@langchain/*` 依赖。
- 保留已有“业务正文先缓冲、审核通过后再发送”的断流修复。
- 审核失败后只允许业务节点再处理一次，第二次业务输出直接返回，不再进入审核循环。
- 中间进度可以保留，但不能暴露“审核未通过”等审核报告。

## 实施步骤

1. 修改 `createReviewedAgent`：第一轮业务输出后执行一次审核。
2. 审核通过：直接输出第一轮业务答案。
3. 审核不通过：隐藏审核结果文本，只向业务节点注入内部纠正消息，再执行第二轮业务节点。
4. 第二轮业务节点输出后直接返回，不再审核、不再输出审核报告。
5. 更新 `test-answer-review.ts` 覆盖通过、不通过返工一次、失败草稿不外泄、最终不含审核文本。
6. 执行 TypeScript 编译和相关测试。
