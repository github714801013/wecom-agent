## Problem Statement

企业微信的 Pi 主执行路径在完成证据检索后仍会调用运行时 Todo 工具更新内部状态，并把 Todo 状态作为最终回复放行的一部分。最近的真实日志显示，最后几轮 Todo 更新本身执行很快，却额外触发模型轮次，造成尾部等待；同时，MCP 的 `list_repos`、`query` 和 `code_snippet` 结果会在 Pi 工具执行边界以较大原文进入后续模型上下文，重复的项目清单、候选结果和代码内容使上下文持续膨胀，增加模型决策延迟和达到请求截止时间的概率。

当前工具结果在企业微信适配层消费事件时才进行过滤，不能保证 Pi 下一轮模型请求读取的是过滤后的内容。因此仅在外层修改消息不能解决上下文膨胀问题。

## Solution

将 Pi 主执行路径的完成语义交还给 Pi 生命周期：移除该路径的运行时 Todo 工具、Todo 指令、状态 bookkeeping 以及依赖 Todo 状态的最终回复放行判断。正常业务完成只接受 Pi 生命周期最后一个有效的非空 assistant 结果，且其 stop reason 为 `stop`；Pi 自主选择工具、继续执行和结束，不由宿主设置工具调用预算、查询次数、递归次数或结果数量作为完成条件。

将工具结果压缩前移到 Pi 工具适配器的 execute 返回边界，使 Pi 从第一轮开始就只看到适合继续推理的内容。已知项目范围时不向该次 Pi 注册 `list_repos`；项目范围未知时才保留该工具，但只返回项目定位所需的最小字段。`query` 和大型 `code_snippet` 结果超过分工具阈值时返回结构化证据摘要，并将受安全存储上限保护的原始结果交给现有的按需读取工具；解析失败也只返回安全占位符，不把完整结果重新送入模型。

## User Stories

1. 作为企业微信用户，我希望证据检索完成后不再看到内部 Todo 更新造成的额外等待，以便更快收到答案。
2. 作为企业微信用户，我希望 Pi 可以自行决定是否继续检索和何时结束，以便复杂问题不会被宿主的 bookkeeping 流程打断。
3. 作为企业微信用户，我希望正常答案只在 Pi 确实以 stop 原因结束并提供非空内容时发送，以便中间文本、取消和异常不会被误当成结论。
4. 作为维护者，我希望主 Pi 路径不再注册运行时 Todo 工具，以便一次 Todo 更新不会触发新的模型轮次。
5. 作为维护者，我希望主 Pi 路径的系统提示不再要求模型维护 Todo 或根据 Todo 放行最终答案，以便完成条件只有生命周期事实。
6. 作为维护者，我希望主 Pi 路径不依赖 Todo 状态判断最终回复是否可发送，以便 Todo 更新失败不会阻塞有效的 `agent_end(stop)` 结果。
7. 作为维护者，我希望 Pi 的 `agent_end` 为 aborted、error、缺少 stop 原因或缺少非空 assistant 文本时不被视为正常完成，以便错误语义保持清晰。
8. 作为维护者，我希望移除 Todo 控制不会引入固定工具次数、查询次数、递归次数或宿主循环上限，以便 Pi 的自主工具选择能力保持不变。
9. 作为维护者，我希望诊断接口和其他仍有独立用途的 runtime-todolist 类型不因本次主路径优化而被整体删除，以便不扩大改动范围。
10. 作为维护者，我希望工具结果在 execute 返回 Pi 之前就被压缩，以便后续模型轮次从一开始就使用受控上下文。
11. 作为维护者，我希望小型工具结果保持原有证据内容，以便压缩不会改变简单查询的回答质量。
12. 作为维护者，我希望大型工具结果在安全存储上限内可通过现有按需读取工具取得，以便减少上下文而不丢失可复核证据。
13. 作为维护者，我希望压缩失败时返回稳定的占位符、文件标识、原始大小和有限定位信息，以便模型知道如何继续取证而不会收到不可控的大 payload。
14. 作为维护者，我希望已知项目范围时不向 Pi 提供完整仓库清单，以便避免一次无关的全局项目发现调用。
15. 作为维护者，我希望项目范围按用户明确目标、会话或默认 MCP 项目提示、最后才是未知范围的顺序确定，以便同一请求的工具集合可预测。
16. 作为维护者，我希望未知范围下的 `list_repos` 结果只包含项目名、路径、分支等定位字段，而不包含统计、过程、嵌入或其他详情，以便模型快速选择候选项目。
17. 作为维护者，我希望未知范围下的完整 `list_repos` 原始结果仍可按需读取，以便最小摘要不会阻止项目核实。
18. 作为维护者，我希望 `query` 大结果的摘要包含候选文件、路径、行号和少量证据片段，以便模型可直接判断下一步是否需要窄范围读取。
19. 作为维护者，我希望大型 `code_snippet` 的摘要优先保留文件路径、行号和证据行，以便代码结论仍可定位和复核。
20. 作为维护者，我希望 `query` 或 `code_snippet` 的摘要无法解析时仍能通过文件读取工具恢复完整结果，以便格式变化不会导致证据丢失。
21. 作为维护者，我希望完整结果只在模型明确调用按需读取工具时进入上下文，以便模型不会被无关尾部内容拖慢。
22. 作为维护者，我希望按需读取工具返回的明确小段内容不会被再次递归存储和压缩，以便读取操作真正提供可控证据片段。
23. 作为维护者，我希望工具错误状态和必要的错误信息在压缩后仍可识别，以便 Pi 能自主决定重试、换工具或结束。
24. 作为维护者，我希望工具仍可被 Pi 自主调用任意次数，以便本次上下文优化不被误解为工具预算控制。
25. 作为维护者，我希望工具顺序执行和取消语义保持不变，以便本次优化只改变结果表示，不改变工具副作用边界。
26. 作为测试人员，我希望能用假工具验证 execute 返回值已经是压缩结果，以便测试不依赖真实模型或远程 MCP 服务。
27. 作为测试人员，我希望能用主请求集成测试验证工具集合不含 Todo、有效 `agent_end(stop)` 直接完成，以便覆盖用户可观察的完成语义。
28. 作为测试人员，我希望能验证取消、error、空文本和非 stop 终态不会发送正常最终答案，以便防止生命周期回归。
29. 作为维护者，我希望能比较压缩前后的工具结果字符量和模型轮次数，以便用真实日志验证延迟是否改善，而不是凭感觉调参。
30. 作为运维人员，我希望压缩和 Todo 移除不改变 request timing 的安全字段和终态分类，以便继续比较优化前后的 p95、取消率和超时率。

## Implementation Decisions

- 主执行路径使用 Pi Primary Execution Path 术语；Pi 自主选择工具、继续和完成，正常完成的唯一业务门槛是最后有效 assistant 消息的 `stopReason === "stop"` 与非空文本。
- 从主执行路径的 agent tool 集合和相关提示中移除 runtime Todo 工具、Todo 指令、Todo 状态更新及依赖其状态的最终放行判断。主流程不再因 Todo 是否完成而阻塞、降级或改写最终结果。
- 保留 runtime-todolist 领域模块及其仍被诊断或其他独立流程使用的公开类型和函数；本任务不做全仓库删除或兼容层重写。
- 在 Pi MCP 工具适配器的 `execute` 返回边界执行结果表示转换，而不是在企业微信适配器消费 ToolMessage 后才修改。模型下一轮可见的内容必须已经经过该转换。
- 结果转换只改变送入模型的表示，不改变工具是否被调用、调用顺序、取消传播、错误状态或 Pi 对继续执行的自主决定。
- 项目范围采用三层判定：用户明确指定的项目优先；没有明确指定时使用当前会话或默认 MCP 项目提示；两者都不存在时才把 `list_repos` 作为可用发现工具注册给该次 Pi。
- `list_repos` 在未知范围时仅保留项目名称、路径、分支等最小定位字段，去除统计、过程、嵌入和其他与初步范围选择无关的详情；原始结果仍保存在现有工具结果临时存储中。
- 通用工具结果上限继续复用现有 20,000 字符边界；`query` 和 `code_snippet` 使用 8,000 字符分工具阈值。阈值是结果表示策略，不是工具调用次数、查询次数或循环完成条件。
- 超过分工具阈值的 `query` 和 `code_snippet` 返回结构化证据摘要，至少包含可识别的候选文件或路径、行号信息和少量证据片段；摘要应优先支持模型决定下一步窄范围读取。
- 大型 `code_snippet` 的完整结果写入现有临时结果存储，摘要携带可供 `tool_result_file_read` 使用的文件标识、原始大小和继续读取提示。`query` 的大型结果采用同一按需读取契约。
- 结果无法解析为结构化证据时，完整结果仍落盘，但 Pi 只收到固定安全占位符、定位元数据和受限预览；禁止以解析失败为理由把完整原文重新送给模型。
- `tool_result_file_read` 是有意的证据恢复操作，其返回的小段内容不应被同一转换逻辑递归存储；仍遵守该工具已有的单次读取上限和安全序列化行为。
- 工具结果压缩应保留工具名称、成功或错误状态及 Pi 继续决策所需的错误信息；不可序列化值继续使用既有固定占位语义。
- 完整原始结果只作为按需读取的数据源，不直接拼接回普通会话历史或主请求最终答案；主请求仍按现有会话持久化契约保存必要的用户问题和最终答案。
- 本次不设置固定工具预算、不设置宿主递归上限、不按结果大小提前停止 Pi，也不把速度分类或上下文大小作为正常完成条件。
- 临时结果使用不可预测文件标识、严格标识校验、私有文件权限、单文件/文件数/总容量上限和 TTL 清理；超过安全存储上限时明确标记未保存的尾部内容，不以无限制持久化换取证据恢复。
- 继续使用现有 `tool_result_file_read` 和临时文件 TTL，不引入第二套结果存储或外部索引。
- 更新项目领域词汇和架构决策记录，明确 Todo bookkeeping 与 Pi 完成语义分离，以及工具证据摘要与完整按需读取之间的取舍。

## Testing Decisions

- 测试只验证外部可观察行为，不锁定私有函数名称、临时文件命名或具体压缩实现；优先在最高可控接缝验证 Pi 实际收到的 execute 返回值。
- 在 Pi 工具适配器接缝使用假 MCP 工具覆盖：小结果保持可用、`list_repos` 最小字段投影、大型 `query` 摘要、大型 `code_snippet` 摘要、解析失败安全占位符、完整结果按文件标识分段读取、成功和错误状态保留。
- 主请求集成测试使用现有 Fake WS/Agent 接缝，验证主 Pi 工具集合不含 runtime Todo、相关系统提示不要求 Todo 完成、有效非空 `agent_end(stop)` 不依赖 Todo 状态即可发送最终回复。
- 生命周期回归测试覆盖 `agent_end` 的非 stop、空文本、error、aborted、普通流结束和工具执行错误；这些情况不得被转换成正常完成。
- 自主性回归测试让假 Agent 在没有 Todo 工具的情况下进行多次工具调用后正常 stop，验证没有新增固定工具次数、查询次数或递归次数门槛。
- 范围判定测试覆盖用户明确项目、会话/默认项目提示、无范围三种情况；已知范围的 agent tool 集合不得包含 `list_repos`，未知范围仍能自主选择该工具。
- 结构化摘要测试使用包含多个候选文件和行号的代表性结果，以及缺少预期字段的格式，验证可定位证据优先、解析失败安全回退且完整内容可恢复。
- 工具结果读取测试验证大结果不会整体进入 Pi 的下一轮输入，模型主动使用 `tool_result_file_read` 后可以按 offset 取得完整内容，读取片段不会递归产生新的文件占位符。
- 运行现有 Pi runtime、工具上下文过滤、工具结果存储、list_repos 范围、TTL 和最终回复交付回归测试；只运行本任务相关的最小范围，不把无关历史测试失败归因于本次变更。
- 通过 TypeScript 编译和 `npm test`，并显式运行新增或未被默认脚本覆盖的相关测试；记录每条命令、退出码和跳过项。
- 性能验收使用部署后的真实 request timing 分层样本，不在单元测试中假定某个模型延迟或固定节省秒数。至少比较多轮请求的工具结果规模、Pi 轮次数、`piModelRoundMs`、总耗时和取消率；由于当前字段包含工具时间，必要时结合 Pi 生命周期时间戳解释。
- 安全验收确认生产 request timing 不包含原始用户内容、完整工具参数或完整工具返回；测试环境受控原文开关不作为压缩正确性的依赖。

## Out of Scope

- 不更换模型、模型 API、模型参数或部署环境。
- 不并行化 MCP 工具，不改变 MCP server 的查询语义、权限或缓存协议。
- 不设置或恢复固定工具总次数、查询次数、递归次数、重试次数或宿主循环上限。
- 不以结果大小、速度分类、Todo 状态或普通流结束作为提前中断、降级或正常完成条件。
- 不整体删除 runtime-todolist 模块，不改造诊断接口或其他独立消费者的 Todo/审核类型。
- 不删除现有 `tool_result_file_read`，不引入新的外部结果存储、日志平台或持久化数据库。
- 不通过压缩直接丢弃完整代码证据；在安全存储上限内的完整大型结果必须保留为按需读取来源，超出上限时必须明确报告受控截断。
- 不修改企业微信回复调度、ACK 隔离、TTL、会话替换和取消语义，除非测试证明本次接线产生直接回归。
- 不把本次优化预期的日志改善写成已达成的 p50、p95 或 p99；真实样本采集和前后对照属于验证阶段。
- 不读取、输出或提交 `.env`、真实配置、凭据或未脱敏生产日志。

## Further Notes

当前已观察到的慢请求中，Pi 多轮阶段约占绝大多数端到端时间，Todo 更新位于尾部额外轮次，工具结果规模则是上下文增长的可疑放大因素。本规格先修复这两个已被日志和代码证据支持的结构性问题；实现后必须重新部署隔离测试环境并采集同类真实请求，再决定是否需要进一步调整模型、MCP 或其他工具策略。

本规格采用安全优先的压缩回退：模型上下文只接收摘要和按需读取提示，受大小、数量和保留期限约束的原始结果留在已有临时存储中。任何摘要器缺陷都不能通过把完整原文重新送入模型来“兜底”。
